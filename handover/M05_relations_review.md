# M05 关系台账与人工审核交接

**状态：** SQLite 人工关系决策历史已实现；Arches 未集成。正式关系语义、MEHR 证据闭包和生产映射仍需签收及验证。

## 当前测试期实现

- `RelationService` 保存人工决定、证据引用、审核人和时间；通过服务接口追加事件，并为同一关系写入两个方向的记录，不执行传递推断。
- 接受的关系至少要求一个 opaque 证据引用；当前不验证完整 R0/R1/R2/TINY_CONTACT/UNKNOWN 领域条件、反向状态一致性或最终叶证据。
- 当前无 Arches 运行依赖，关系历史在 SQLite 中；Arches 候选许可与部署说明仅适用于将来集成，不构成本原型依赖。

## 模块职责

承载人工接受、撤销、拒识和 UNKNOWN 判断所需的证据引用、审核状态及项目关系记录。模型输出只是候选，不自动成为关系真值；Truth/GT 只在授权、隔离的流程中按需引用，不复制进 Arches 或模型可见域。

## 项目/数据库/许可证

- **Arches（未集成候选）：** 可供未来评估为登记/关系审核工作流，但本原型未采用。若后续接入，M02 与 M05 共用服务。官方[合规指南](https://www.archesproject.org/license-compliance/)要求包清单标注 `AGPL-3.0-only`，但 [PyPI 8.1.6 元数据](https://pypi.org/project/arches/8.1.6/)列为 `AGPL-3.0-or-later`，须按实际源码/发行包核实，不自行择一认定。Arches 通用资源关系不是 RelicWeave 语义层；审核通过后必须由项目验证器映射/校验并导出版本化 MEHR/关系包。
- **关系包/权威契约：** 由经人工审核、项目规则校验后的版本化 MEHR/关系包承载；具体文件格式与落盘后端未选。若未来采用 Arches，可保存审核工作流记录，但未经导出校验不作为唯一真值；原始 Truth/GT 包不存入 Arches。
- 不将 FAISS 或分析 Parquet 作为关系主记录。

## 正式接入前的目标实现

1. 关系领域规则独立于 UI/数据库实现，并由 validator 检查持久化记录。
2. 记录每条关系及其方向、端点、语义状态、来源和直接证据引用；具体字段以 MEHR/schema 为准。R2 直接接触证据须满足项目已有双向/事件/最终叶规则。
3. 区分历史接触、当前几何可贴合和当前可见性；磨损不删除历史 R2。R2 不传递；`TINY_CONTACT` 与 `UNKNOWN` 单列，不并入普通负例。
4. R0、R1、R2、TINY_CONTACT、UNKNOWN 必须按正式定义及证据来源维护；不从 same-parent 或模型相似度推导 R2。
5. 审核流程保存“接受/撤销/拒识/补采”等实际业务操作及其关联证据。操作者字段、时间戳和签名/审计格式如何实现待身份系统确认，不能先宣称具备不可篡改审计。
6. M02 与 M05 共用同一 Arches 服务。导入导出须保留项目 ID、schema 版本和证据引用；通过序列化、反序列化及停用迁移测试前，不把 Arches 图模型当唯一真值来源。

## 许可证风险

Arches 的上游许可证表述差异及其实际依赖均为发布门禁；按最终版本/发行物核实。当前 Scribus 独立桌面运行，只经审核文件交接，不进入 Arches 镜像/安装包；这是工程边界，不是二者必然冲突的判断。详见 [LICENSE_REGISTER.md](../LICENSE_REGISTER.md)。本模块不构成法律意见。

## 交接验收

- R2 负例覆盖缺失反向记录、不同事件、非最终叶和无直接子片证据；R2 不发生传递闭包。
- R1 只有同一母体确认且非直接接触证据时成立；R0 与 R1 不由相似度单独判定。
- UNKNOWN/TINY 保持独立，并能表达证据不足/边界模糊。
- 预测候选、人工决定和 GT 事实可区分；撤销决定不会擦除历史证据。
- 任意持久化后端都可导出与项目关系 schema 等价的数据和证据闭包。
