# M09 质量与功能验收、审计收据交接

**状态：** 测试期质量/功能 JSON 收据和本地哈希链审计已实现；签名、正式阈值、身份、保留策略和独立审计存储尚未实现。

## 当前测试期实现

- `AcceptanceService` 分开汇总调用方提交的质量与功能检查，保留 `PASS`、`FAIL`、`BLOCKED` 结论并写入 JSON 收据；这些检查项和结论不是独立验证出的系统事实。
- `AuditService` 将本地事件按前序 hash 串联并可校验/导出 JSONL；有数据库写权限者可重建整条链，因此它不是签名或防篡改审计系统。
- 当前无第三方运行依赖，收据及事件元数据存于 SQLite/本地文件；正式收据 schema 与保存策略仍待项目签收。

## 模块职责

把各流程阶段的输入版本、校验结论、功能结果、错误和人工处置统一关联，支持质量验收与功能验收分别报告。M09 汇总证据，不代替业务负责人签署，不把单一 PASS 外推为数据物理有效或整个项目验收通过。

## 项目/数据库/许可证

- JSON 收据、日志、manifest/hash 是当前材料支持的证据形式；其具体 schema、签名方式、存储介质和保留时间未定。
- 本模块未选择第三方项目或数据库；新增日志/SBOM/签名库时再登记许可证。

## 正式接入前的目标实现

1. 收集 M03 校验、M04 快照、M05 审核/关系、M07 统计和 M08 产物的只读引用及版本/hash。
2. 将数据质量和系统功能分开：例如格式/引用/授权/资格规则结果与导入、检索、人工审核、报告生成等功能结果分别记录。
3. 保存每个阶段进入的样本数、通过数、失败数、拒绝/隔离数和未评估数；沿用项目定义的失败分母和指标口径，不擅自重定义指标。
4. 把每次重新采集、重新构建、复核、模型/规则升级视为新证据记录；不覆盖已有收据。是否采用不可变日志/签名由安全设计确认。
5. 验收失败时只触发建议的补采、重建、复核或 STOP 路径；不得自动修改 Truth/GT 或关系真值。
6. 许可证合规与数据内容授权作为发布门禁证据单列，不能只看 SBOM 通过就视为考古数据可公开。

## 交接验收

- 任一统计值、报告或索引可回指数据快照、规则/代码版本和输入 hash。
- 全流程失败分母保留，分子/分母口径在收据和报告中一致。
- 未签署、未评估、未知状态不能被编码成通过。
- 失败复跑保留旧记录并能说明差异；任何人工覆核可回溯到授权流程。
- 生产发布前，许可证与数据权利审查的责任人与状态明确。
