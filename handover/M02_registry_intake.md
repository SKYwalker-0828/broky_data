# M02 来源登记与导入清理交接

**状态：** SQLite 本地登记与人工审核已实现；Arches、OpenRefine 均未集成。是否在生产采用及如何映射正式数据模型尚未决定。

## 当前测试期实现

- `RegistryService` 将输入文件登记为 M01 资产，并在 SQLite `records` 表保存原型字段；首次授权、物理资格和训练资格均为 `unknown`。
- `curator` 可更新测试期审核字段；系统记录审核前后值及 opaque 证据引用，但不核验真实许可文件，也不构成可信身份或法律审查。
- 当前无 Arches/OpenRefine 运行依赖；只使用 Python 标准库、SQLite 与本地文件适配器。以下候选许可说明仅适用于未来实际选定并集成时。

## 模块职责

记录样品/资产来源、采集或生成上下文、许可、导入批次和处理状态；对外部表格做可审查清理，并把登记结果交给结构和项目质量门。登记通过不等于物理有效、可用于训练或可公开。

## 项目/数据库/许可证

- **Arches（未集成候选）：** 曾评估用于业务登记、资源记录和人工工作流；当前未决定采用。若后续试点，M02 与 M05 可共用一套独立服务。官方[合规指南](https://www.archesproject.org/license-compliance/)要求包清单标注 `AGPL-3.0-only`，但 [PyPI 8.1.6 元数据](https://pypi.org/project/arches/8.1.6/)列为 `AGPL-3.0-or-later`。该差异须按实际源码/发行包核实，不自行择一认定。具体版本、依赖发行物、部署方式及数据模型映射仍待验证。
- **OpenRefine：** 导入前表格清理可选工具；上游 [`LICENSE.txt`](https://github.com/OpenRefine/OpenRefine/blob/master/LICENSE.txt) 为 BSD-3-Clause。它不是登记台账的权威数据库。
- Arches 官方 8.1 依赖文档列出 PostgreSQL/PostGIS、Elasticsearch、GDAL/GEOS、Python、Node 等依赖；实际锁定版本、发行包与部署方式须按试点版本核定。此处不指定 Arches 以外的独立登记数据库。
- 若未来采用 Arches，它只承载登记/审核工作流和便于检索的业务记录；关系结果须经项目自定义规则校验并导出为版本化契约数据，未经转换的 Arches 记录不作为唯一关系真值。
- Arches 与 Scribus 分别作为服务端工作流和桌面排版步骤独立运行；两者不共享容器、安装包、代码或运行时依赖。该边界不是许可证冲突判断，见 [许可证清单](../LICENSE_REGISTER.md) 和 [总体复核](../REVIEW.md)。

## 生产候选实现方法

1. 导入先保留输入文件原件及 hash，复制到工作副本后再清洗；清洗操作、规则与导出结果应可复查。
2. 在 Arches 试点中先用少量合成/授权样本映射业务概念，验证来源记录、许可状态、审核角色和导出/回读闭包；不得直接让 Arches 通用关系逻辑成为 RelicWeave 关系真值。
3. 对导入批次标记来源、责任人、时间和上游文件引用；具体字段以现有契约和项目批准的采集表为准。
4. OpenRefine 只作为预处理步骤，不把清洗结果覆盖原文件；清理后仍运行 M03 的完整质量与资格检查。
5. 若 Arches 未通过许可证、数据模型、权限或运维评估，停止生产采用并保留模块适配边界；本草案不预选替代项目。

## 数据边界

来源许可、物理资格、ML 使用角色、split、公开/再分发权分别记录。实采样品、现代授权样品、合成样品不可因使用相同导入格式就合并资格语义。VesselForge 已废弃，不录作生产入口。

## 许可证注意事项

部署或修改 Arches 时，按官方指南和实际网络/分发方式审查源代码提供、许可证文件、版权声明及依赖。当前不把 Scribus 与 Arches 组合发行；仅作人工文件交接。若改变此决定，需重开版本级审查。OpenRefine 分发时保留 BSD 条款要求的声明；此交接不构成法律意见。

## 交接验收

- 原输入与清理输出可以区分并回溯。
- 缺失来源、许可未知、物理资格未知和训练用途未知被明确表示，而不是默认通过。
- 同一实体跨来源/合成孪生的分组按项目要求登记或标记待确认，不按文件名猜测。
- Arches 原型证明记录可导出/可迁移，且业务字段不丢；实际 schema 由项目所有者签收。
